# 增加一个自主活动

当前插件是经过验证的数据包，不执行 DLL、JavaScript 或 Python。它能组合宿主已支持的移动、预约、持物、动画、抛接、设施准备和休息能力；新增一种宿主没有的物理机制仍需扩展核心 API。不要把改标题的同一场景计为全新动作。

可以从 `content-packs/basketball` 复制一份开始，使用新的反向域名 `id`，并保持自己的物品、设施、活动和素材 ID 在该命名空间内。

| 文件/字段 | 用途 |
|---|---|
| `manifest.json` | 包身份、版本、核心版本范围、能力需求、容量预算、活动入口 |
| `activities[].subscribe` | 在库存、天气、设施、可用角色或闲暇窗口变化时重新判断 |
| `activities[].when` | 角色可用、无紧急需求、主要家务不急、时间、天气和设施等条件 |
| `chance` | 在指定机会窗口抽取一次，避免每帧反复抽签把低概率变成必然 |
| `cooldown_world_ms` | 冷却使用世界时间，和真实陪伴时钟无关 |
| `participants` | 人数、角色类型和是否需要同意 |
| `max_rounds` / `max_duration_world_ms` | 有界轮数和最长占用时间 |
| `rules/items.json` | 真实道具与获得方式 |
| `rules/facilities.json` | 设施占地、站位和材料要求 |
| `scenes/*.json` | 有序步骤、成功分支、失败分支与收尾 |
| 素材索引与图集 | 每帧身份、来源、锚点、像素和打包校验 |

庭院篮球示例在干燥的 15–18 点、两人空闲且没有紧急家务时判断机会，概率为每个合格午后窗口 1/5，冷却两个世界日。准备场地和获得球是独立的前置过程，缺球不会直接进入比赛。

一次完整活动依次邀请、同意、预约球场站位、走到器材处、取球、走到场上、运球、传球、接球、投篮、按结果反应、捡回球、换人，最后归还道具并休息。拒绝、失败或中断也必须解除预约、保留唯一道具并完成合理收尾。

安装入口位于程序右键菜单的插件菜单。选择 `.catpack` 后宿主检查版本、路径、图集、预算、引用和可达步骤；不兼容或超预算包不会直接进入世界。禁用/卸载也应等待或处理已在进行的活动，不把人和球凭空删除。

重建示例包：

```powershell
python tools/build_basketball_pack.py
```

此开发脚本需要 Pillow；玩家运行 EXE 和安装已构建包不需要 Python。包作者应分别验证不点击也会触发、抢占时正常退让、临时缺料、角色拒绝、存读中途活动、卸载期间收尾，以及画面外模拟和画面内模拟结果一致。
