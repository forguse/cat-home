# 旧版 5,000 条的正式村庄接入边界

旧版 5,000 是目录条目：400 个角色基础行为、24 个共享基础规则、2,600 个角色变体、1,076 个共享变体、900 个配对变体。它们不等于 5,000 套独立动画，也不是正式村庄已经自然触发的 5,000 种完整事情。

正式村庄不能直接运行旧 `cast.rs` 的效果枚举。旧规则有些仅凭天气、场景或角色在场就改变庭院；正式版本必须走真实路径，取得实际工具和库存，预约工作站，再提交结果。以下表区分这轮完成的机制和还缺的机制；不能把“类似代码存在”计成整条共享规则已实现。

## 所有新行为共同遵守的流程

条件满足 → 能力与场地检查 → 预约实际站位 → 到来源地拿工具或物品 → 按真实行程到场 → 呈现动作 → 扣除来源并提交唯一结果 → 交接或归还 → 释放预约。失败分支必须保留物品所有权、允许重试或退回，不能把取消动作当成交易成功。

居民手持图来自真实 `VisitorHeld`。摊货从自有库存打包，走到柜台后上架。主人公的出行物品由出行托管袋持有。绘制读取实际持有和交接状态，旧素材内画死的商品没有库存凭证。

1.1.2（2026-11-14）接通了现有服务目录内 **34 条物件移动服务**与 **37 条消耗材料的服务**。物件从登记的来源站位实地取走，在途中由同一角色持有，抵达约定站位后放置或交接。修补、筹备与家庭服务需要先从指定库存取出实物。取消后，有剩余的物件或材料要走回来源交还，保留归属与预约直到该步结束。居民侧 40 项聚焦测试通过，2,000 世界日回放完成所验证的全部 23 项社会进度。这些计数覆盖现有服务，旧目录仍有未接通的变体。

成熟街区增加按需照料。橘子饥饿达到 90、碗空且仓中至少有一份饭时，已完成开场生活流程、没有更急需求的照料人可从库存取一份饭，搬至原有猫碗。橘子到场后实际吃掉。家庭取水按可用的近井派工，已出发的旧行程继续前往原井。市集备货和邻里晚餐只给现有农事、钓鱼、料理安排提供有界需求，章节的库存和结果条件沿用原值。

步行以现实耗时控制，游戏时钟仍是白天 48 倍、夜间 96 倍。搬运、疲劳和恶劣天气影响速度，跨越晨昏也保持连续。放慢步行后，约饭、营业准备、取货和施工必须重新核对行程预算。

## 24 个共享基础规则逐项口径

| ID | 意图 | 正式村庄现状或需要补齐的机制 |
|---|---|---|
| S01 | 窄路互让 | 已有桥头及站位预约和侧移避让。井口有人取水时，其他路线绕开工作站位。两位主角相向且一人占着对方的工作目标时，离开站位的人先走，另一人侧移并有界等待，重新打开存档后能继续。其他物种的通用会车仍待接入。 |
| S02 | 熟悉位置短停 | 仍需每个角色有界的最近停靠记忆及空位检查，不能只随机停住。 |
| S03 | 同伴停步 | 部分共同用餐/约会有集合等待；通用结伴行走仍需小队目标及分离恢复。 |
| S04 | 檐下避雨 | 有雨天作息及服务条件；需保留被打断任务、实际屋檐站位和雨停恢复，才算完整通用规则。 |
| S05 | 飞鸟落点互让 | 待建立飞行落点排他预约，不把空中随机偏移算完成。 |
| S06 | 借阴影移动 | 需实际光照/阴影路线及物种适用限制，目前未完整接入。 |
| S07 | 小动物穿缝 | 需按体型分层通行和真实入口/出口，不能穿过普通碰撞格。 |
| S08 | 软地足印 | 实际完成相邻移动后，在合格湿地或雪地留迹。最多 32 处，过期或降水清除，不写进存档。当前适用两位主角和橘子。 |
| S09 | 收工清场 | 已接入上述服务的实物返还与预约释放。仍需为更多工位增加真实散料状态与清扫任务。 |
| S10 | 草木随风 | 需植物姿态和统一风场；不依赖随机变色冒充动画。 |
| S11 | 叶雨入土 | 需叶面蓄水量与土壤水转移，不能额外无来源加水。 |
| S12 | 光照变化反应 | 有昼夜画面变化；每个角色有限的亮度事件记忆及反应尚未通用化。 |
| S13 | 打量新设施 | 需设施版本/最近见过的对象及安全站位，避免每天重复“第一次见”。 |
| S14 | 空资源换目标 | 有库存复查、替代工作、满仓退回和真实备料。低库存会调度实际耕作、钓鱼或料理，仍受工具、场地和当前任务约束。其余访客及动物的变体尚未逐一接入。 |
| S15 | 顺风滑翔 | 待风场及飞行速度权威规则。 |
| S16 | 试探松边 | 待可改变的边坡/崩落格、退步和修复规则，不能只做受惊表情。 |
| S17 | 围观散去 | 有来访及预约容量；需保存原目标并为围观分配有限外围位置。 |
| S18 | 修后试用 | 部分工程有实际检查步骤；需逐设施定义验收结果及返工条件。 |
| S19 | 寻找同伴 | 待单条最后看见位置、时效与找不到后的恢复规则。 |
| S20 | 绕过落枝 | 有路径重算；需真实新增/移除落枝的生命周期，不能只有装饰图片。 |
| S21 | 新叶向光 | 待植物批次朝向记录与光照累积；不得每个时段无限追加叶片。 |
| S22 | 惊响回避 | 待有界声音事件、距离/参与者排除以及临时回避，不应打断紧急生存需求。 |
| S23 | 绕水洼 | 已有禁止踏水和实际寻路；动态浅水边界、退水恢复及边沿水纹尚需完整机制。 |
| S24 | 空出停留位 | 交易和实物服务使用真实站位预约，家庭工作站位可有界互让。群体活动的统一座位重排与恢复原目标仍待接入。 |

## 扩充次序及验收

优先复用地面角色的 S01/S02/S03/S04/S09/S13/S14/S18/S24；每类先做完整成功、被抢占、缺物资、天气中断、保存恢复六个分支，再开放已有目录里的角色/场景变体。飞行、松边、向光需要新的物理状态，不提前标记完成。

一个变体只有改变有效触发条件、对象或结果，并有能力约束、可到达站位、物资守恒、可见动作和中断恢复，才登记为“已接入”。同一句话换天气或角色名称不新增机制计数。动画可复用，但要显式写清对应动作与工具；缺视觉的条目单列。

每次上线只增加有限注册项。运行只保存当前任务、少量最近记忆和冷却时间；不永久记录每次触发，不逐日累积场景实例。旧 5,000 条保持设计来源身份，不能并入当前原生互动已实现数量。
