# 柳溪村地图修订 3 的存档迁移

地图修订 3 保持布局 ID、192×128 格和旧的 12 个阶段编号，增加末位 `map_dense_r3`。新增的实心树、岩石和篱笆使用该阶段同时控制碰撞与可见性。编译检查在关闭这一位后与修订 2 的底图、碰撞和互动几何等价。地图修订号升为 3，存档容器仍使用 schema 4。

## 选址条件

- 保留道路、桥、边界走廊、坡岸、水域、剧情路线、原有地表与落脚位置。只在修订 2 可走的干地添加新固体。每块被封的连通区域都要留有从其中走到新版公共路网的旧路出口，且改变后的可走区域要维持原连通性。
- 保留所有阶段的门、地籍、施工材料位、预留搬迁房基及门前等候格、站位及其接近路径、生产树根与工位、田块、公共设施和插件地籍。保护代码引用的原有固定位置，包括旧宅三处兼容房基、临时床、猫的休息路径、阶段灯位与地面维护位置。
- 保留居民和访客可选的摊位、检查点、收货点、等候区、返还地点和社交会面的相邻候选格。固定野生动物路线需覆盖整段连续轨迹、岸上及水面位置、避难位置及其分期坐标偏移。渲染与寻路使用同一阶段。

## 读取和安全启用

首先按修订 2 几何验证原档。存档头、世界内的修订号和阶段位必须一致。完整验证家庭、居民、访客、插件及各方预约，保留真实时钟、镜头、施工和搬家进度，以及持物、包裹、账本、工具和活跃合同。插件沿用原版本定义的保存边界，按原有机制恢复已存角色预约。验证或写入失败时保留原档，旧档不会变成新开档。新版首存前写入原档的逐字节备份 `world-v4-map-r2-<SHA3-256>.json`，已存在的同名备份必须逐字节一致。

迁移先升级修订号，暂不打开新增几何。新档直接开启该阶段。已出发的相邻一步保留起点、终点和时间，不会跳过半步。每次尝试开启时检查人物和访客的脚格与已开始一步的终点，同时核对正在等候和操作的目标及固定动物路线。足位安全后，在同一个世界时刻切换可见性与碰撞。受影响的未走路尾从下一合法落点按原任务目标重新搜索。已结算的交易、在途物品、订单和预约继续由原持有人负责。

旧版允许插件物件留在当时任意可走的落点。若其中有物件正压住新景物位置，除该格外的密度仍可启用。该格在碰撞和绘制中一起沿用旧地形，待实际取回物件、返还预约结束、脚格与已开始一步都让开后再补上景物。这类例外按坐标去重并保存，最多 79 格，对应既有 32 个插件引用、1 个飞行落点和 23 种服务物件的存放与取回地点，不逐日增长。

## 验收

验证新增障碍正好处在旧脚格、旧路线的下一承诺步、尚未承诺的路尾时，分别检查延迟启用、连续走出和保留任务重寻路。覆盖携物家庭成员、商户、访客、屋内停留、插件场地及动物轨迹。至少从当前玩家、365 日和 730 日修订 2 副本分别运行生产入口，保存并重开，记录几何实际启用的耗时、阶段状态和旧存档副本哈希。任何一个样本仍停留在等待启用都要报告，不计为该样本完成升级。
