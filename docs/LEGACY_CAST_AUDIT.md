# 旧版 5,000 条行为的柳溪村接入审计

以 1.1.4 默认启动的柳溪村为历史基线，当时有 **0 条旧 ID 直接绑定**。下表保留首次审查。现行逐 ID 表另读正式登记，区分基础执行入口和可匹配场景。游戏只在角色确实完成动作后记录实际发生的一个 ID。登记数、当前档见到的数量和独立动画数是三个不同的量。

## 目录组成与审计结果

| 映射判定 | 基础条目 | 场景变体 | 合计 | 依据 |
|---|---:|---:|---:|---|
| 同核未绑定 | 21 | 0 | 21 | 现有村庄能做同一核心动作，逐条注明新旧角色、目标或画面差异。 |
| 可小规模接入 | 45 | 0 | 45 | 有可用角色、场地和产权接口。仍需为具体条件、动作和结果编排一次真实工作。 |
| 变体上下文待绑定 | 0 | 1,053 | 1,053 | 来源基础可复用。时段、位置、强度、时效和同伴还要逐项接线。 |
| 有局部机制需改编 | 137 | 1,298 | 1,435 | 有通用的类似功能，原物件、触发或结果至少有一项缺口。 |
| 缺所需机制 | 200 | 1,095 | 1,295 | 遇到巢、风向、枝条、微水路、特殊材料或野生个体关系等缺口。 |
| 缺角色或名单不匹配 | 20 | 338 | 358 | 由旧巡夜人或气象观察员主导，或要求他们参与。 |
| 原条件不可达 | 1 | 792 | 793 | 以当前原生条件无法自然触发。 |
| **总计** | **424** | **4,576** | **5,000** | 每个旧 ID 一行，无重复。 |

424 个基础 ID 包含 400 项角色专属和 24 项共享行为。角色专属中有 31 条基础就需要同伴。4,576 个场景来自 384 个基础 ID，包含 2,600 项单角色、1,076 项共享及 900 项配对变体。45 对角色各有 20 个场景。30 行角色出场配置、24 行效果配置、30 个条件掩码及 556 个场景索引桶只描述生成和查找方式。基础表共使用 24 类效果、16 类目标、6 种姿态和 22 个道具词。

审计表保留每行旧 ID、来源条件、位置、同伴、三种效果模式之一、原作者条件与结果，以及当前角色、候选位置、代码证据、判定和画面缺口。77 项基础有单独审读并配置了候选结论。其余条目保留逐项原文，依据当前机制族分档，仍需在各自开发任务中审定专门物件和结果。每条变体都另核对角色、配对和明确的气候条件。兼容的自然出场条件也只代表有机会看到角色，真实工位预约仍待实现。

几个重要边界包括以下情况。

- 冬季天气机制会把降雨候选画成降雪，归入原条件不可达的 358 个条目来自这种冲突。萤火虫当前只在晴朗夏夜出现，旧目录只有春、秋、冬，因此旧萤火虫场景不能直接套入当前日历。
- H03-04 的作者文字要求无降雨，旧数据却标为雨天。基础及其 25 个场景须先统一条件。保留两份原文供裁定。
- H04 巡夜人和 H05 气象观察员缺少同职居民。现有灯、天气和鸟类观察员各自有职责。H02 园艺师的工作由花晴、林枝和阿谷分担，逐动作选人。
- 旧 A01 橘猫对应家庭的橘子。A02 到 A20 都有同类的野生条目。野生巡游、4 张黑猫画面或一张睡姿本身不能完成独立睡眠、寄居、关系或配对条文。翠鸟与乌龟不在这 5,000 条的角色名录。

## 现行居民适配

| 旧基础 ID | 当前实际流程 |
|---|---|
| H10-01、H10-02、H10-10 | 谷芽在私柜取一批种，抵达且柜台营业时清点。买家携 2 份余菜实地交换 3 粒种子，未成交的原袋由原人退回。收摊后，谷芽在原柜退回未售种子，剩货和售出数与装出数核平。 |
| H07-01、H07-05、H07-06 | 米信从实际短札存放点收件。原信实地交给家人后仅加一次邮戳。原预约凭条取出两世界小时仍未交到场的收件人时退回原址。提前取消同样退回，单独记录真实逾期的情况。 |
| H06-09 | 厨师带实际熟食批到营业柜台，菜单显示可核的份数与最多两个当日预约额度。预约失败会释放额度，已有买卖使用原料、成餐和双方库存。这里将旧厨房工作预约改编成到场买餐预约。 |
| H09-01、H09-06、H09-10 | 夏墨从自己的固定四块可复用画板中带一块出门，到真实果树花期或可见西屋的晴静池边作画，完成后带回门廊。展架最多三幅，下一幅到场替换旧板。果树花期适配旧花畦。没有作完的原板带回收好。 |

具体可匹配旧变体由现行执行登记限制角色、时段、天气、位置和实际模式。现有画稿和观察动作共用实际工作画面，餐食菜单、回执和种袋没有自动兑现原目录中的额外种子、额外食物和多种独立动画。

## 首次审查的优先候选（历史筛选）

以下保留实现前的筛选依据。最终 1.1.5 已接入 24 项基础、41 个精确变体；当前逐项结论见[本版实现](LEGACY_BEHAVIORS_1_1_5.md)。21 条同核和 45 条候选是首次审查分类，不能当成全部已交付数量。

| 先做的 ID | 用正式村庄的什么 | 必须检验 |
|---|---|---|
| S08 | 两主角和橘子的湿地脚印。 | 只在真实相邻步落地后出现。不同体型、旧时效限制和抹除条件清楚。 |
| S09、H10-10 | 原工位卸货、物件归还、摊位收摊。 | 有可追溯余料或剩货，现场取走并回原归属。收摊后还可以再次预约。 |
| S14 | 到场再核对真实资源的剩余量，必要时走到另一处。 | 空点等待、同一演员、替代站位和原持物均能核验。 |
| S18 | 一处已修设施的实地试用，例如已修工具或桥面。 | 记录实际试用。失败时设施仍待修，标志不会因先前付料自动完成。 |
| H01-17、H01-26、H01-37、H01-48 | 采菜并留种、真实排水、取食送猫、到场收同一封信。 | 田畦及水量真的变化。餐、菜、种和信的同一批物品能追到交接或使用。 |
| H06-09、H07-06、H10-02 | 按实际柜台库存挂牌、原凭条退回、柜台用余菜换种。 | 依真实库存和预约释放，贸易到场再校验，两方数量守恒。 |

后续可接已经审过的会车、檐下避雨、合法座位让位以及有真实碰撞的落枝或浅水绕行。需要先补角色、巢窝、统一风场或动物状态的条目独立排期。无需先实现 5,000 个函数。可以由有限能力和原生任务消费经过校验的变体参数。每加入一个变体都应能说明触发条件、已发生的结果或动作为何有效。外观或标题变化仍可作为场景风味。

所有接入都经过实际角色、地图权限、到场、来源取得物或工具、成功提交、取消归还和保存重播验证。引擎保持有限任务、占位和冷却槽。正式绑定数只在代码可执行且有证据后增加，保持与基础、变体、画面帧数分开。

## 画面证据

现有村庄 20 位居民有各自常态图。图集有 40 张居民专属走路帧，默认绘制实际使用其中 14 张。其余 13 位居民使用各自头部和共享身体姿态，以实际持有物变换工作画面。野生图集 100 帧中，默认巡游加专项避让明确引用 73 帧。旧模式的 30 个角色分用相同姿态类别和时间帧，规则和变体共同引用。施工、投递、收货和一些脚印已有可复用的表现。风中压弯、通用筑窝、完全不同的画稿、独立门闩与不同种类实物仍按需求补素材和状态。
